# Phase 3A prototype — PROTOTYPE / SYNTHETIC DATA ONLY

Technical validation of the Phase 2 architecture (`../PHASE_2_ARCHITECTURE_DECISION_RECORD.md`).
Findings are in `../PHASE_3A_TECHNICAL_VALIDATION_REPORT.md`.

> **Never point this code at a real database.**
> - `src/lib/db.ts` refuses any host other than `localhost`/`127.0.0.1`.
> - All data is generated by `sql/*.sql`. No names, phone numbers or payments of real people exist anywhere.
> - "Archive storage" is a local directory (`.archive-store/`) standing in for an S3-compatible bucket.
> - Nothing here connects to Supabase-hosted projects, object storage, WhatsApp, email or any scheduler.

## Requirements

- Docker. The official image `supabase/postgres:17.6.1.066` runs locally, limited to 0.5 CPU / 512 MB as a rough stand-in for Free-plan compute.
- Node 22+.

## Run everything from scratch

```bash
cd prototype
npm install
./scripts/run-all.sh      # start DB → seed → env capture → P1…P10 → late-data → summary
```

This takes about 5 minutes on a 4-core host. Each prototype writes `results/<id>.json` (checks, measurements, notes), and `results/summary.json` holds the pass/fail table.

## Run one prototype

```bash
./scripts/start-db.sh && npx tsx src/seed.ts   # once
npx tsx src/p1-freezing.ts                     # or p2 … p10, late-data
```

Prototypes mutate the synthetic databases (they archive and delete synthetic rows). For exact reproduction of the committed results, use `run-all.sh`, which reseeds first.

| Script | Validates |
|---|---|
| `p1-freezing.ts` | Exact PK + row-fingerprint freezing; changed, deleted, new and backdated rows |
| `p2-whole-day.ts` | Whole-day rule incl. 124,999 + 60/70/80 = 125,209; time zone; NULL dates; edge cases |
| `p3-fk-graph.ts` | FK graph discovery, derived delete order, CASCADE/SET NULL/RESTRICT, cycles, orphan prevention |
| `p4-formats.ts` | CSV.GZ vs JSONL.GZ vs Parquet vs XLSX: size, speed, restore fidelity |
| `p5-verification.ts` | V1–V8 verification; 8 corruption cases → DELETE = 0 |
| `p6-delete-performance.ts` | Batch sizes 500 to 10,000 with a concurrent synthetic app; lock-timeout retry |
| `p7-failure-resume.ts` | Crash at 10 points, lease/duplicate prevention, kill switch, nested-transaction guard |
| `p8-schema-change.ts` | Add/drop/rename/type/constraint/FK changes between verification and deletion |
| `p9-rls-role.ts` | Least-privilege archiver role, RLS partial/zero visibility, BYPASSRLS |
| `p10-storage.ts` | Size, dead tuples, vacuum, space reuse, VACUUM FULL, read-only mode (dedicated DB) |
| `late-data.ts` | New/backdated/modified rows around the freeze, end to end through the job runner |

## Layout

```
sql/            synthetic schemas + data (RosiFit-like, Jalsa-like, control plane)
src/lib/        db (safety rail), schema/fingerprint, fkGraph, group (selection), archive (freeze+export),
                verify (V1–V8), deleter (exact batches), jobRunner (leases, checkpoints, crash injection)
src/p*.ts       one script per prototype
results/        committed JSON evidence from the last full run
```

The whole-day selection reuses the Phase 1 function `src/lib/domain/selection.ts` unchanged.
