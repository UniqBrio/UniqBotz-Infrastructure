## 3. Read-only discovery procedure (to be executed by an authorized operator)

**Scope: READ-ONLY DISCOVERY ONLY.** No archive capability, no job, no deletion.

**Prerequisites:**

- checklist SB-1/SB-2;
- the hosted validation has passed (`HOSTED_SUPABASE_VALIDATION_RUNBOOK.md`);
- authentication is configured before any production data is shown in the dashboard. The API refuses anonymous reads once a production application is registered.

1. **The RosiFit owner creates a dedicated monitor role** in the RosiFit database (SQL editor, as `postgres`). The password is generated and held by the owner; it is never committed.
   ```sql
   CREATE ROLE uniqbotz_monitor LOGIN PASSWORD '<generated by owner>' NOINHERIT CONNECTION LIMIT 2;
   ALTER ROLE uniqbotz_monitor SET default_transaction_read_only = on;
   ALTER ROLE uniqbotz_monitor SET statement_timeout = '30s';
   GRANT USAGE ON SCHEMA public TO uniqbotz_monitor;
   GRANT SELECT ON ALL TABLES IN SCHEMA public TO uniqbotz_monitor;   -- needed for exact counts / growth; omit to keep catalog-only
   -- NO INSERT/UPDATE/DELETE/TRUNCATE, NO BYPASSRLS, NO service-role key.
   ```
2. **Store the password in the worker's secret store** as `ROSIFIT_MONITOR_PASSWORD`. Never put it in the repository or the control plane.
3. **Register RosiFit as a production application with monitoring only.** The control plane refuses `archive: true` for production applications (constraint `production_is_read_only`).
   ```json
   {
     "id": "rosifit", "name": "RosiFit", "supabaseProjectRef": "lhpzhkzbnquwjljmbylo", "environment": "production",
     "status": "active", "timeZone": null, "enabled": true,
     "capabilities": { "monitoring": true, "archive": false }, "databaseCapacityMb": <plan quota — decision AP-9>,
     "connections": { "monitor": { "purpose": "monitor", "host": "<session pooler or direct host>", "port": 5432, "database": "postgres",
       "user": "uniqbotz_monitor<.ref if pooler>", "passwordRef": "env:ROSIFIT_MONITOR_PASSWORD", "sslMode": "verify-full", "statementTimeoutMs": 30000 } }
   }
   ```
   `timeZone` stays `null` until decision AP-1. Growth then reports `CANNOT RUN — APPLICATION TIMEZONE NOT CONFIGURED`, by design.
4. **Run discovery:**
   ```bash
   npx tsx worker/cli.ts register rosifit.json
   npx tsx worker/cli.ts discover rosifit ROSIFIT_READ_ONLY_DISCOVERY_REPORT.generated.md
   ```
   The worker:
   - uses the monitor connection with `default_transaction_read_only = on`;
   - reads catalog and statistics;
   - counts exactly only tables with ≤ 200k estimated rows or near a threshold;
   - never reads row contents;
   - marks **every table REVIEW_REQUIRED**;
   - audits the run as `discovery_report`.
5. **Check the generated report's safety lines before anything else:**
   - "session read-only: yes";
   - "Write privileges of the connected role: None". If there is a **WARNING**, the owner must remove the extra grants before the role is used again.
6. **Merge the generated report into §4 below.** Keep the observed/assumed separation. Commit it; it contains metadata only.
7. **Stop.** No retention policy is changed as part of discovery. Classifying tables is a separate, reviewed step (checklist AP-2…AP-6).
